**這個資料夾完全獨立，不會影響現行 pipeline。** 只讀 `../real_color_translet/` 的原圖，
只寫 `./output/`。沒有修改 `teeth_test.py`、`preprocess_photos.py` 或其他任何檔案。

## 執行

```bash
/home/Zhen/anaconda3/envs/triposr/bin/python fluorescence_plaque_test.py
```

參數：

| 旗標 | 說明 | 預設 |
|---|---|---|
| `--z` | z-score 門檻，越低越靈敏 | 2.0 |
| `--fp-rel` | 紅螢光強度須為該影像牙齒中位數的幾倍 | 1.5 |

輸出：`output/{name}_overlay.png`（結果疊圖）、`_mask.png`（二值 mask）、
`_panel.png`（五格 debug 面板）、`results.json`（數值與區塊統計）。

## 為什麼不能沿用現行的 HSV 門檻

藍紫光下整張影像 R≈B 高、G 低，菌斑的 HSV 色相在 H=6~54 之間亂跳、飽和度只有 47~73，
落在 `teeth_test.py` 的 `H∈[145,172]∪[0,15]` 之外。實測把現行規則原封不動跑在這兩張照片上：
標註的粉紅螢光**一個都沒抓到**，反而在嘴唇、反光燈珠上誤觸發 9 個輪廓。

## 方法：三端元光譜解混

每個像素的 BGR 視為三種光的線性疊加：

```
observed = a·V + fe·E + fp·P

V = 405nm 激發光反射（幾乎不含綠色分量）
E = 琺瑯質綠色自體螢光
P = 菌斑紅色螢光（porphyrin ~635nm）
```

三通道三未知數 → 每像素直接解 3×3 線性系統，取 `fp` 當菌斑強度。

**關鍵好處**：牙齒與紫色牙齦的交界看起來偏紅，但那份紅可以完全由 `V` 解釋，`fp` 趨近 0。
先前試過的 Lab a\* 局部對比法，最強訊號其實是這圈**邊緣偽影**而不是菌斑，完全抓錯目標。

之後再對 `fp` 做局部背景相減 + MAD 自適應門檻，消除左右照明梯度，
且門檻不綁死絕對數值 —— 換相機、拍攝距離、曝光都不必重調。

牙齒 ROI 用 **G 通道**取（琺瑯質有強綠色自體螢光、軟組織幾乎沒有），
在這種暗場照片上比 YOLO/SAM 穩，且不需要載模型。

## 已知限制

- **樣本只有 2 張**，`z_thresh` / `fp_rel_min` 有 overfit 風險。之後有更多照片時，
  優先確認 z 門檻是否還適用；端元估計（V、E）本身是每張圖自動算的，不需調。
- `P` 端元目前寫死為純紅 `(0,0,1)`。若之後拿到菌斑的實測發射光譜，換成實測值會更準。
- 目前沒有 FDI 齒位對應。要接上現有的 3D 投影流程時，需要把 G 通道 ROI 與
  `extract_plaque_regions.py` 的 SAT FDI mask 取交集 —— 那是整合階段的事。

# v2：適應環境光的版本（plaque_detect_v2.py）

第二批 12 張照片（IMG_5030~5086）是同一套設備、不同角度拍的，畫面裡會出現
手術鋪單、器械線、手指、舌頭，而且混入診療室環境光。v1 在這批上幾乎全錯，
所以另開 `plaque_detect_v2.py`（`fluorescence_plaque_test.py` 保持原樣不動）。

## v1 在這批失敗的原因

| | 4955/4956 | 新的 12 張 |
|---|---|---|
| 平均 B / 平均 R | 1.50、1.64 | 0.90 ~ 1.10 |
| G>60 的像素比例 | 14% | 19% ~ 50% |

有環境光時「軟組織幾乎沒有綠色」不再成立，Otsu 把黏膜、舌頭、嘴唇、手指、
甚至藍綠色手術鋪單都算成牙齒（ROI 佔全圖 25~34%）。ROI 一錯，
從 ROI 內估出來的琺瑯質端元 `E` 跟著錯（IMG_5082 估到鋪單，變成藍色最大），
解混結果完全失去物理意義（IMG_5034、5067 的 `fp` 中位數直接是 0）。

## v2 的修正：牙齒 ROI 加上通道比值閘門

實測各類物體的通道比：

| 區域 | B/G | R/G |
|---|---|---|
| **牙齒** | **0.76 ~ 0.84** | 0.97 ~ 1.07 |
| 手術鋪單（teal） | 1.36 ~ 1.72 | 0.71 ~ 1.65 |
| 舌頭 / 口底 | 1.87 ~ 3.08 | 2.06 ~ 2.39 |
| 手指 | 1.85 | 2.97 |

**只有牙齒的綠色自體螢光會壓過藍色**。加上 `B/G < 1.0` 與 `R/G < 1.6` 兩道閘門後，
ROI 從 25~34% 收斂到 5.5~17%，鋪單、舌頭、嘴唇、手指全部排除。

## 成效

以 52 個標註點（容差 = 長邊 5%）評估：

|---|---|---|---|---|---|
| 4955 | 2/2 | 2.4% | 5067 | 4/4 | 2.9% |
| 4956 | 3/3 | 2.9% | 5074 | 3/3 | 2.3% |
| 5030 | 1/2 | 2.0% | 5082 | 3/4 | 1.0% |
| 5034 | 1/2 | 1.9% | 5083 | 4/4 | 6.6% |
| 5043 | 2/4 | 4.1% | 5085 | 3/4 | 2.1% |
| 5044 | 2/2 | 2.0% | 5086 | 3/4 | 2.9% |
| 5055 | 5/8 | 1.9% | **總計** | **42/52 = 80.8%** | |

菌斑佔牙齒面積從 v1 的 6~11%（過度觸發）回到 1~4%，與 4955/4956 同一量級。

## 標註 ground truth 工作流

```bash
# 1. 把紅圈標註圖放進 annotated/（檔名含 IMG_xxxx，截圖原樣即可）
# 2. 抽成正規化座標

# 3. 看 annotated/verify_*.png 確認位置抽對了
```

## v2 已知限制

- **precision 尚未量化**，目前 80.8% 只是 recall，且容差 50px 偏寬鬆。
- **激發光端元 `V` 仍不穩**。它是從「G 最低的前 20% 像素」估的，

  這兩張的命中有運氣成分，是下一步要處理的地方。
- `manual_points.json` 是目測抄錄，其中 5034 的點 1、5055 的點 4、5067 的點 1
  疑似偏離牙齒，待使用者確認或改用程式抽取。

# v3：V 端元物理約束與 precision 量化

第三批照片（`real_teeth/*4_test.jpg`）附帶紅圈標註，且使用者確認
`front3_test`、`front4_test` **兩張正面視角幾乎沒有菌斑**——這是第一次拿到
確認乾淨的負樣本。

## 改動

**1. 標註抽取支援「原圖的局部裁切」**

這批標註圖不是完整影格（`4_front_test` 比例 1.253 vs 原圖 0.750），
不能等比例換算。改用多尺度樣板比對（先 inpaint 掉紅筆畫還原底圖，
再用 NCC 搜尋位置與尺度）定位回原圖，5 張的比對分數 0.99~1.00。

檔名對應新增 `<n>_<view>_test` → `real_teeth/<view全名><n>_test.jpg` 規則。

**2. `V` 端元加物理約束**

405nm 紫光的藍必為最大分量、綠必須很小。自動估計違反時代表取樣到的
不是紫色背景（有環境光時會取到紅棕色牙齦），退回暗場校準值
`(1.0, 0.033, 0.367)`。**5 張裡 4 張觸發退回。**

| | 修正前 | 修正後 |
|---|---|---|
| 菌斑佔牙齒面積 | 4.7 ~ 10.4% | **2.1 ~ 5.2%** |
| `upper_occlusal` precision | 50% | **83%** |
| recall | 100% | 100%（維持） |

**3. `plaque_detect_v2.py` 改為委派 `fluorescence_core`**

它原本有一份自己的 `estimate_excitation` 複本，正是參數漂移的來源。
現在演算法只有一份，449 → 309 行。

**4. 評估新增 region-level precision**

每個偵測區塊的質心是否落在任一標註的容差內。像素級 IoU 需要全圖標註
成本太高，區塊層級也更貼近實際用途（醫師在意「有沒有指對牙」）。

目前：新批次 recall 14/14 = 100%；舊批次 recall 42/52 = 81%、precision 65%。

## ⚠️ 未解決：乾淨影像仍會誤報

`front4_test` 經使用者確認幾乎無菌斑，卻仍偵測出 13 個區塊。

**根本原因：MAD 自適應門檻是純相對的**，永遠會標出每張圖裡最紅的前幾 %，
系統沒有「這張圖乾淨」這個狀態。抓到的可能是琺瑯質本身的正常變異
（染色、厚度差、濕潤反光）。

### 已排除的修法（附數據，勿重複嘗試）

| 嘗試 | 結果 |
|---|---|
| 邊緣距離閘門 | 誤報離 ROI 邊界**反而更遠**（中位數 8.1 vs 命中的 6.8），precision 不變 |
| 縮小形態學閉運算核 0.012→0.004 | precision 27% → 29% |
| 閉運算後重新色彩過濾 | 完全無變化 |
| 加大 ROI 內縮 0.004→0.030 | 乾淨影像仍有 15~21 個誤報，recall 掉到 64% |
| 絕對 `fp/fe` 門檻 | **反向重疊**，見下 |

```
front3_test（確認乾淨）   p50 0.02  p90 0.10  p99 0.23
left_side4_test（有菌斑） p50 0.02  p90 0.08  p99 0.18
```

確認乾淨的影像每一個統計量都**高於**有菌斑的影像。不是門檻沒調好，
是 `fp/fe` 這個特徵無法分離「乾淨」與「低量菌斑」。

誤報也不在牙齒邊緣或牙齦乳突，而是散在牙齒表面，顏色簽名
（B/G 0.84、R/G 1.17）與真菌斑（0.82、1.22）幾乎一致。

### 解法：影像層級絕對閘門（已實作）

先前的門檻全是相對的，所以必然會在每張圖標出東西。加一道**絕對判準**：

```python
"image_gate_pct": 90,      # 取牙齒區域 fp/fe 的第 90 百分位
"image_gate_min": 0.12,    # 低於此值 → 判定整張無菌斑，輸出空結果
```

用 `fp/fe` 而非 `fp` 是關鍵：實測 29 張紫光照片的 `fe` 變異
**CV 僅 12%**（手機自動曝光是對著亮的牙齒測光，等於已幫忙正規化），
所以這個比值是曝光無關的，絕對門檻才能跨影像成立。

各影像實測值：

| 影像 | p90(fp/fe) | 狀態 |
|---|---|---|
| front4_test | 0.073 | 使用者確認乾淨 |
| left_side4_test | 0.083 | 2 個淡標註 |
| front3_test | 0.097 | 使用者確認乾淨 |
| lower_occlusal4_test | 0.163 | 1 個標註 |
| upper_occlusal4_test | 0.334 | 5 個標註 |
| right_side4_test | 0.335 | 6 個標註 |
| 舊批次 14 張 | 0.145 ~ 0.369 | 全部有標註 |

門檻掃描：

| 閘門 | 乾淨圖誤報 | recall | precision |
|---|---|---|---|
| 無（原本） | **21 個** | 100% | 23% |
| **0.12（採用）** | **0 個** | 86% | 41% |
| 0.20 | 0 個 | 79% | 71% |

**成效：兩張確認乾淨的正面照，誤報從 21 個歸零；舊批次 14 張零誤殺**
（recall 81%、precision 65% 均未變動）。

觸發時結果會標記 `image_gate_triggered: true`，前端可據此顯示
「本次未偵測到明顯菌斑」。設 `image_gate_min: 0` 停用，
`plaque_detect_v2.py` 另有 `--gate` 參數可即時試值。

### 取捨與限制

- **`left_side4_test` 的 2 個淡標註會被漏掉。** 它的 0.083 夾在兩張乾淨影像
  （0.073、0.097）之間，資料上就落在「幾乎乾淨」區，沒有任何門檻能把它
  與乾淨影像分開。目前設定偏向**寧可漏報也不誤報**；若臨床上淡菌斑必須抓到，
  門檻降到 0.07 以下可抓回，代價是乾淨影像回來約 8 個誤報。
- **0.12 是用僅 2 張乾淨樣本定出來的**，之後有更多確認乾淨的照片時應重新檢查。
- **precision 65% 這個數字仍不完全可信**——分母裡混了「真誤報」與「使用者沒圈
  但其實是菌斑」。可信的證據是那兩張確認乾淨影像的誤報歸零。要讓 precision
  變得可信需要「完整標註」（圈出一張圖裡所有菌斑）而非代表性標註，
  挑 2~3 張做校準基準即可。

### 其他可能的出路（尚未採用）

- **A. 拍攝時加入校正參考物** — 畫面裡放已知白色/螢光標準片，或固定曝光，
  讓 `fp` 可跨影像比較，絕對門檻才有意義。最正確但要改拍攝流程。
- **B. 累積資料改用學習式分類器** — 需要數十張確認過的正負樣本。
- **C. 改變輸出語意** — 不宣稱「有/無菌斑」，改成相對熱區排名，
  覆蓋率當相對指標。最誠實、零成本，但功能定位改變。

短期建議 C，中期規劃 A。
