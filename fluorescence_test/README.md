## 為什麼不能沿用現行的 HSV 門檻

藍紫光下整張影像 R≈B 高、G 低，菌斑的 HSV 色相在 H=6~54 之間亂跳、飽和度只有 47~73，
落在 `teeth_test.py` 的 `H∈[145,172]∪[0,15]` 之外。實測把現行規則原封不動跑在這兩張照片上：
標註的粉紅螢光**一個都沒抓到**，反而在嘴唇、反光燈珠上誤觸發 9 個輪廓。

## 方法：三端元光譜解混

每個像素的 BGR 視為三種光的線性疊加：

```
observed = a·V + fe·E + fp·P

V = 405nm 激發光反射（幾乎不含綠色分量）
E = 琺瑯質綠色自體螢光
P = 菌斑紅色螢光（porphyrin ~635nm）
```

三通道三未知數 → 每像素直接解 3×3 線性系統，取 `fp` 當菌斑強度。

**關鍵好處**：牙齒與紫色牙齦的交界看起來偏紅，但那份紅可以完全由 `V` 解釋，`fp` 趨近 0。
先前試過的 Lab a\* 局部對比法，最強訊號其實是這圈**邊緣偽影**而不是菌斑，完全抓錯目標。

之後再對 `fp` 做局部背景相減 + MAD 自適應門檻，消除左右照明梯度，
且門檻不綁死絕對數值 —— 換相機、拍攝距離、曝光都不必重調。

牙齒 ROI 用 **G 通道**取（琺瑯質有強綠色自體螢光、軟組織幾乎沒有），
在這種暗場照片上比 YOLO/SAM 穩，且不需要載模型。

## 已知限制

- **樣本只有 2 張**，`z_thresh` / `fp_rel_min` 有 overfit 風險。之後有更多照片時，
  優先確認 z 門檻是否還適用；端元估計（V、E）本身是每張圖自動算的，不需調。
- `P` 端元目前寫死為純紅 `(0,0,1)`。若之後拿到菌斑的實測發射光譜，換成實測值會更準。
- 目前沒有 FDI 齒位對應。要接上現有的 3D 投影流程時，需要把 G 通道 ROI 與
  `extract_plaque_regions.py` 的 SAT FDI mask 取交集 —— 那是整合階段的事。

# v2：適應環境光的版本（plaque_detect_v2.py）

第二批 12 張照片（IMG_5030~5086）是同一套設備、不同角度拍的，畫面裡會出現
手術鋪單、器械線、手指、舌頭，而且混入診療室環境光。v1 在這批上幾乎全錯，
所以另開 `plaque_detect_v2.py`（`fluorescence_plaque_test.py` 保持原樣不動）。

## v1 在這批失敗的原因

| | 4955/4956 | 新的 12 張 |
|---|---|---|
| 平均 B / 平均 R | 1.50、1.64 | 0.90 ~ 1.10 |
| G>60 的像素比例 | 14% | 19% ~ 50% |

有環境光時「軟組織幾乎沒有綠色」不再成立，Otsu 把黏膜、舌頭、嘴唇、手指、
甚至藍綠色手術鋪單都算成牙齒（ROI 佔全圖 25~34%）。ROI 一錯，
從 ROI 內估出來的琺瑯質端元 `E` 跟著錯（IMG_5082 估到鋪單，變成藍色最大），
解混結果完全失去物理意義（IMG_5034、5067 的 `fp` 中位數直接是 0）。

## v2 的修正：牙齒 ROI 加上通道比值閘門

實測各類物體的通道比：

| 區域 | B/G | R/G |
|---|---|---|
| **牙齒** | **0.76 ~ 0.84** | 0.97 ~ 1.07 |
| 手術鋪單（teal） | 1.36 ~ 1.72 | 0.71 ~ 1.65 |
| 舌頭 / 口底 | 1.87 ~ 3.08 | 2.06 ~ 2.39 |
| 手指 | 1.85 | 2.97 |

**只有牙齒的綠色自體螢光會壓過藍色**。加上 `B/G < 1.0` 與 `R/G < 1.6` 兩道閘門後，
ROI 從 25~34% 收斂到 5.5~17%，鋪單、舌頭、嘴唇、手指全部排除。

## 標註 ground truth 工作流

```bash
# 1. 把紅圈標註圖放進 annotated/（檔名含 IMG_xxxx，截圖原樣即可）
# 2. 抽成正規化座標
python extract_annotations.py        # → annotated/reference_points.json
# 3. 看 annotated/verify_*.png 確認位置抽對了
# 4. 跑偵測，命中率會自動評估
python plaque_detect_v2.py
```

`plaque_detect_v2.py` 優先讀 `reference_points.json`（程式抽取，像素級），
沒有的話退回 `manual_points.json`（目測抄錄，誤差較大，目前用的是這份）。
標註只影響 console 與 `results.json` 的評估數字，不會畫在輸出圖上。

## v2 已知限制

- **precision 尚未量化**，目前 80.8% 只是 recall，且容差 50px 偏寬鬆。
- **激發光端元 `V` 仍不穩**。它是從「G 最低的前 20% 像素」估的，
  在有環境光時那批像素是紅棕色牙齦而非紫色背景，導致 IMG_5082 的
  `V=[1.00, 0.53, 0.96]`、IMG_5083 的 `V=[0.94, 0.53, 1.00]` 變成紅色最大。
  這兩張的命中有運氣成分，是下一步要處理的地方。
- `manual_points.json` 是目測抄錄，其中 5034 的點 1、5055 的點 4、5067 的點 1
  疑似偏離牙齒，待使用者確認或改用程式抽取。
